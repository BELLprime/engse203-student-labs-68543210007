# AI_USAGE — LAB 09

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

> ผู้สอนจะสุ่มถามจากโค้ดที่ส่ง — ถ้าอธิบายไม่ได้ คะแนนส่วนนั้นจะถูกทบทวน

## ครั้งที่ 1

**ถามอะไร**
- สอบถามเกี่ยวกับกลไกการทำงานของ Logical Operators ใน SQL เมื่อต้องการกรองข้อมูลที่มีหลายเงื่อนไขพร้อมกัน และความแตกต่างระหว่างการใช้เครื่องหมายจุลภาค `,` กับโอเปอเรเตอร์ `IN (...)` ในประโยค `WHERE`

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- ใน SQL เครื่องหมาย `,` ไม่สามารถใช้เป็นตัวดำเนินการเปรียบเทียบในเงื่อนไขได้เนื่องจากผิดไวยากรณ์ หากต้องการตรวจสอบว่าค่าในคอลัมน์ตรงกับกลุ่มข้อมูลใด ๆ ในเซต ต้องใช้โอเปอเรเตอร์ `IN (...)` หรือเปรียบเทียบทีละเงื่อนไขด้วย `OR` ส่วนการรวมหลายเงื่อนไข (เช่น ตรวจสอบทั้งสถานะและความเร่งด่วน) ต้องเชื่อมด้วย `AND` ที่มีนิพจน์สมบูรณ์ทั้งสองฝั่ง

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำความเข้าใจเรื่องไวยากรณ์ `IN` และการเชื่อมเงื่อนไขด้วย `AND` ไปเรียบเรียงคำสั่งกรองคำร้องเร่งด่วนที่ยังไม่เสร็จใน `queries.sql` (ข้อ ③) ด้วยตนเอง

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2

**ถามอะไร**
- สอบถามแนวคิดการดึงข้อมูลข้ามตารางด้วย `JOIN` ในระบบฐานข้อมูลเชิงสัมพันธ์ (Relational Database) ว่ามีกลไกจับคู่แถวข้อมูลผ่าน Primary Key และ Foreign Key อย่างไร รวมถึงประโยชน์ของการตั้งชื่อย่อตาราง (Table Alias)

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- การ `JOIN` คือการนำข้อมูล 2 ตารางมาประกบคู่กันในระดับแถว โดยอาศัยเงื่อนไขที่ระบุหลัง `ON` ซึ่งโดยมาตรฐานจะนำ Foreign Key จากตารางที่อ้างอิง (`requests.requester_id`) ไปจับคู่กับ Primary Key ของตารางหลัก (`users.id`) ส่วนการใช้ Table Alias (เช่น `r`, `u`) เป็น Best Practice ที่ช่วยให้อ่านโค้ดง่าย ลดความซ้ำซ้อน และป้องกันการพิมพ์ชื่อตารางผิด

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำหลักการสร้างสะพานเชื่อมตาราง (`ON r.requester_id = u.id`) ไปเขียนคำสั่งดึงข้อมูลคำร้องร่วมกับข้อมูลผู้ใช้งานใน `queries.sql` (ข้อ ⑤) และต่อยอดใส่เงื่อนไขกรองภาควิชาในข้อ ⑥

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 3

**ถามอะไร**
- สอบถามหลักการทำงานของคำสั่ง `DISTINCT` ในระดับฐานข้อมูลว่ามีกระบวนการคัดกรองแถวข้อมูลที่ซ้ำซ้อนอย่างไร และส่งผลต่อผลลัพธ์อย่างไรเมื่อทำงานร่วมกับการ `JOIN`

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- `DISTINCT` จะทำการตรวจสอบข้อมูลในคอลัมน์ที่ระบุหลัง `SELECT` ทั้งหมด หากพบว่ามีแถวใดที่มีค่าตรงกันทุกคอลัมน์ ระบบจะตัดแถวที่ซ้ำออกให้เหลือเพียงรายการเดียว การนำมาใช้ร่วมกับ `JOIN` จึงช่วยแก้ปัญหาผู้ใช้หนึ่งคนที่มีประวัติส่งคำร้องหลายรายการไม่ให้ชื่อปรากฏซ้ำซ้อนในรายงาน

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำหลักการตัดข้อมูลซ้ำด้วย `DISTINCT` ไปเขียนคำสั่งสรุปรายชื่อผู้แจ้งที่ไม่ซ้ำกันใน `queries.sql` (ข้อ ⑦)

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 4

**ถามอะไร**
- สอบถามสาเหตุและที่มาของข้อผิดพลาด `ambiguous column name` เมื่อมีการเชื่อมตารางที่มีชื่อคอลัมน์ซ้ำกัน และหลักการทำงานของ `LIMIT` ร่วมกับการเรียงลำดับแบบย้อนกลับ (`ORDER BY ... DESC`)

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- เมื่อทำการ `JOIN` ตารางที่มีคอลัมน์ชื่อเหมือนกัน (เช่น คอลัมน์ `id` ที่มีทั้งใน `users` และ `requests`) ตัว Query Engine จะไม่สามารถตัดสินใจเองได้ว่าต้องการอ้างอิงคอลัมน์จากตารางใด จึงต้องระบุ Table Prefix นำหน้าให้ชัดเจน (เช่น `r.id`) เสมอ ส่วนการหาข้อมูลล่าสุด จำเป็นต้องเรียงลำดับจากมากไปน้อย (`DESC`) ก่อนเสมอ เพื่อให้ `LIMIT` ตัดเฉพาะแถวบนสุดที่เพิ่งสร้างขึ้นจริง

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำความเข้าใจเรื่องการแก้ปัญหาชื่อคอลัมน์กำกวมและลำดับการประมวลผลของ `ORDER BY ... DESC LIMIT ...` ไปเขียนคำสั่งดึงคำร้องล่าสุดใน `queries.sql` (ข้อ ⑧)

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 5

**ถามอะไร**
- สอบถามเกี่ยวกับวงจรการทำงาน (Execution Order) ของ `GROUP BY` ร่วมกับ Aggregate Functions เช่น `COUNT(*)` ว่ามีลำดับการประมวลผลข้อมูลในฐานข้อมูลอย่างไร และนำไปประยุกต์ใช้กับระบบงานจริงอย่างไร

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- ในกระบวนการประมวลผล SQL ระบบจะจัดหมวดหมู่ข้อมูลตามค่าในคอลัมน์ที่ระบุ (`GROUP BY`) จากนั้นฟังก์ชันรวม เช่น `COUNT(*)` จะทำการนับจำนวนแถวในแต่ละกลุ่ม และสุดท้ายจึงนำผลลัพธ์ที่ได้มาจัดเรียง (`ORDER BY`) ซึ่งในระบบจริงเป็นหัวใจหลักในการสรุปตัวเลขสถิติ (Metrics/Aggregation) เพื่อนำไปแสดงผลบน Dashboard ของเว็บแอปพลิเคชัน

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำแนวคิดการจัดกลุ่มและการนับจำนวนไปออกแบบคำสั่งสรุปจำนวนคำร้องแยกตามสถานะการดำเนินงานในส่วน Challenge (ข้อ ⑨) ของ `queries.sql`

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ
